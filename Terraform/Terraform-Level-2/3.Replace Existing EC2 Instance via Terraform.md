### `main.tf`
```
resource "aws_instance" "web_server" {
  ami           = var.ami_id
  instance_type = var.instance_type

  tags = {
    Name = var.instance_name
  }
}
```

Terraform manages infrastructure by comparing your desired configuration (`main.tf`) against its recorded state (`terraform.tfstate`). Normally, if your configuration files haven't changed, Terraform sees no reason to touch an existing resource like your EC2 instance.

However, using `-replace` overrides this behavior and forces Terraform to act as if the resource configuration *did* change, compelling it to tear down the old instance and spin up a fresh one. This specific capability is essential in environments where you need to validate deployment automation, test system recovery, or force underlying cloud changes without altering your codebase.

To complete your lab task and verify everything is working:

1. Open your terminal in VS Code (right-click the explorer area and select **Open in Integrated Terminal**, or use an existing terminal) and change to the working directory:
