An issue has arisen with a static website running in a container named `nautilus` on `App Server 1`. To resolve the issue, investigate the following details:

1. Check if the container's volume `/usr/local/apache2/htdocs` is correctly mapped with the host's volume `/var/www/html`.
2. Verify that the website is accessible on host port `8085` on `App Server 1`. Confirm that the command `curl http://localhost:8085/` works on `App Server 1`.




---
To inspect an exited container using standard Docker commands. Here are the three main ways to look into it:

### 1. Check Container Logs

To see any stdout/stderr output or error messages emitted before it exited:

```bash
docker logs nautilus

```

---

### 2. Inspect Container Details (Mounts, Port Mappings, Exit Code)

To view detailed JSON metadata (including mount configurations, environment variables, and reason for failure):

```bash
docker inspect nautilus

```

You can filter specifically for volume mounts to see how the volume was set up:

```bash
docker inspect -f '{{ json .Mounts }}' nautilus | jq

```

---

### 3. Copy Files Out of the Exited Container

Even though the container is stopped, its filesystem is preserved. You can copy files or directories out to the host to examine them:

```bash
docker cp nautilus:/usr/local/apache2/htdocs /tmp/extracted_htdocs

```

---

### Note on Running Commands Inside

You **cannot** run interactive commands (like `docker exec -it nautilus bash`) while it is exited. If you need to explore the filesystem interactively, commit the stopped container to a temporary image and run a shell inside a new container:

```bash
docker commit nautilus debug-nautilus
docker run --rm -it debug-nautilus sh

```

# 🌟🌟🌟
This happens when a container is started interactively without detached mode (`-d`), or when its attached terminal session/tty closes. Docker sends `SIGWINCH` / `SIGTERM` when the foreground process loses its terminal, causing Apache to exit. Additionally, the container wasn't bound to host port `8085`.

---

### Solution

Recreate the container in **detached mode (`-d`)** with port `8085` mapped to container port `80`:

1. **Remove the stopped container:**
```bash
docker rm nautilus

```


2. **Run a new detached container with the correct volume and port mapping:**
```bash
docker run -d --name nautilus -p 8085:80 -v /var/www/html:/usr/local/apache2/htdocs httpd

```


3. **Verify it stays running and serves the website:**
```bash
docker ps
curl http://localhost:8085/

```
